= ddot.it

Specification, documentation website and shared test corpus for ddot.it ("double dot"), a minimal plain-text syntax for writing typed links and properties anywhere text can be entered, forming a decentralized knowledge graph.

[[purpose]]
== Goal, purpose, area

ddot.it defines a line-oriented triple syntax (subject, relation and object separated by double dots) plus metadata introduced by a double comma.
The idea (from `README.md`): readers extract triples from many kinds of sources (such as Markdown, YAML, AsciiDoc and HTML), a collector combines them into one knowledge graph in Connected JSON format, and humans and AI agents can share it across tool boundaries.
This repository holds the normative spec, user and developer guides, a manifesto, and a cross-implementation test suite that parsers (such as the VS Code extension) check themselves against.
Area: knowledge graphs, personal and enterprise knowledge management, notation design.

[[nature]]

Business / open-source product of Max Völkel's brand ddot.it, hosted under the Calpano GitHub organisation.

[[structure]]
== Major parts and entry points

.Parts
* `site/` -- Jekyll source of https://ddot.it (theme just-the-docs); `index.adoc`, `syntax.adoc`, `user-guide.adoc`, `developer-guide.adoc`, `manifesto.adoc`, `spec/`, `reader/` (per-format reader docs), `llms.txt`
* `docs/` -- internal docs for parser developers (`parsing-procedure.adoc`, `parser-devs.adoc`, `syntax-summary.adoc` and more)
* `test-data/` -- shared test corpus: numbered `cases/` (about 40), an EBNF grammar `ddot.ebnf`, `tokens.md`, and `regenerate-html.rb`
* `tools/scope-map.json` -- mapping of grammar scopes (likely for syntax highlighters)
* `check.sh`, `check-links.sh`, `check-vocabulary.sh` -- quality checks on the site
* `serve.sh` -- local Jekyll preview; `render-images.sh` -- renders diagrams (PlantUML)
* `_config.yml`, `Gemfile` -- Jekyll site configuration
* `.github/workflows/pages.yml`, `vocabulary.yml` -- GitHub Pages deployment and vocabulary check

[[content]]

* Docs: AsciiDoc (~34 files), Markdown (README files), HTML (expected outputs of test cases and site templates)
